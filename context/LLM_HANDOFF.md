# Agent handoff

Start a new session with:

```text
Continue work in /Users/stripes/Documents/GitHub/mctree-mchome. Read AGENTS.md and context/LLM_HANDOFF.md first. Preserve manual edits and run git status --short before editing.
```

This repository is McFamily, a static family atlas. Version `0.0.1.64` uses a latest-only schema v13 browser namespace and strict dataset 16.0.x packages internally. Normal recipients use one public Pages link: `core/cloud.js` anonymously fetches a ciphertext-only JSON vault from the public `themadat/app-data` repository, then PBKDF2 plus AES-GCM opens the selected Owner, named Editor, named Private Viewer, or named Redacted Viewer grant entirely in the browser. Owner and separately named Editors decrypt the full record and may publish; publication audit automatically uses the signed-in username. Owner alone adds, rotates, or removes up to 20 grants for each non-Owner role. Private Viewers decrypt full PII read-only but have no person or family Notes interface. Redacted Viewers receive only a separately encrypted package where places, residences, contacts, family Notes, and unstructured record notes were removed before encryption. Read-only modes omit routine recovery ZIP, import, PDF, developer-data, and publishing controls. Imported Source appears and participates in search only for Owner/Editor in Developer Mode. The passphrase gate reappears on every reload and the encrypted vault is never service-worker cached. There is no custom backend, account provider, cloud database, or runtime dependency.

The main product invariants are now the hosted passphrase gate, strict decrypted-package validation, directory/tree/profile workspace, single Notes modal, Settings/Roadmap, Owner recovery, encrypted GitHub publication, themes, accessibility, and install shell. Do not restore the removed Records interface, multi-note workspace, rich-text editor, or plaintext automatic synchronization.

## Workflows

### `wish`

Record an idea in `context/WISHES.md` without planning or implementing it.

- Check for duplicates and use the next `WISH-###` id.
- Capture behavior, rationale, priority, effort, acceptance criteria, constraints, affected files, and material open questions.
- Set the status to `Proposed`.

### `plan`

Investigate a wish without implementing it.

- Create or revise `context/WISH-###-slug-PLAN.md`.
- Put a `## Resume` section first, followed by decisions, scope, non-goals, file map, accessibility/responsive considerations, tests, and open questions.
- Link it from the wish and set the status to `Planned`.
- Do not change runtime files, build ids, or cache ids.

### `start`

Implement an approved plan.

- Read the wish and plan, set the wish to `Active`, and keep Resume current.
- Add only the architecture the feature needs; keep the app static and dependency-free.
- Preserve the schema-v13 privacy, validation, latest-only storage, accessibility, and offline invariants below.
- Advance the four-part application version and verify affected workflows.

### `cut`

Finalize an active line as a release.

- Confirm the semantic version and reset build to `1` for a new major/minor/patch unless another value is requested.
- Update config identity, release notes, asset queries, manifests when needed, and service-worker ids.
- Mark the wish Shipped and record version/date.
- Run `docs/TESTING.md`.

Do not silently move between lifecycle stages.

## Data and privacy invariants

- Never commit a real family CSV, ZIP, spreadsheet, PDF, screenshot, name list, address, phone, email, heritage note, or family note. Private McLineage CSVs and McFamily ZIPs under `data/` are ignored; use synthetic committed fixtures only.
- Normal first launch requires an online encrypted vault plus a valid hosted passphrase. Before revision 1 exists, an existing local Editor workspace may initialize Owner setup from one validated recovery ZIP. There is no loose-CSV, demo-family, blank-family, JSON/GEDCOM, or deployed bypass path. `?local=1` bypasses only on localhost for UI testing.
- The public data repository contains only the JSON vault: AES-GCM ciphertext, salts/nonces, PBKDF2 iterations, wrapped random keys, access labels/modes, dataset version, timestamp, and revision. Passphrases, GitHub tokens, readable CSVs, and ZIPs must not enter it.
- Owner and each named Editor grant wrap both full and redacted data keys so an existing publisher can update both ciphertext payloads without knowing viewer passphrases. Dynamic recipient ids use `editor-…`, `pii-…`, or `redacted-…`; original fixed role ids remain accepted for version-1 vault compatibility. All shown names are unique, and the signed-in Owner/Editor label is the immutable actor for a publication. Each Private Viewer wraps only the full key; each Redacted Viewer wraps only the redacted key. Removing a grant blocks future reloads but cannot erase previously viewed or copied information. Viewer sign-ins are not centrally auditable without a backend or viewer write credential.
- Maximum family size is 1,500 people.
- The strict five-file ZIP remains the internal validated plaintext representation and the Owner recovery artifact. It is not the ordinary recipient handoff. Imports replace; they do not merge. Later replacement and person deletion create recovery first.
- Deleting the final person leaves an initialized empty workspace.
- Parent and partner links are explicit records. A parent row stores Lineal/Non-Lineal role separately from biological/adopted/step/foster/guardian/unknown type. Reject missing references, self-links, duplicates, a second Lineal parent for one child, and directed ancestry cycles; accept multiple distinct Non-Lineal parents without requiring them to be partners of the Lineal parent.
- Derive ancestors, descendants, siblings, units, and lineage labels; do not cache them on people.
- Use only `mcfamily.state.v13` and `mcfamily.recovery.v5`; do not load, unwrap, or migrate earlier browser state or recovery snapshots. Startup removes only older versioned McFamily state/recovery keys so obsolete copies cannot exhaust the local-storage quota.

## Application invariants

Owner additionally sees the required Owner grant plus dynamic named lists for Editors, Private Viewers, and Redacted Viewers, with passphrase generation/rotation/revocation. Custom phrases require eight characters; the built-in generator creates three-word phrases and the UI warns that short phrases are easier to guess from a public encrypted vault. Owner and Editors see current-family publication, GitHub connection, recovery ZIP, and person/family Notes controls. Viewer modes expose none of those surfaces. Imported Source additionally requires Developer Mode and is excluded from ordinary search. Publications require a summary, derive the actor from the signed-in grant, advance one `16.0.x` patch, append `published-hosted-family`, `created-hosted-access`, or `updated-hosted-access`, revalidate both packages, and use vault revision plus GitHub SHA to reject stale writes. ## Version invariant

Versions use `major.minor.patch.build`. Every completed application update increments build. A major/minor/patch change resets build to `1` unless the user specifies another number. Keep `identity.version`, `identity.buildId`, newest dated release, `index.html` queries, and `sw.js` cache/build ids identical.
